# W5 · 第 5 周：评测（全课程最重要的一周）

> **这一周学的东西，是你和"只会做 demo 的人"之间的分水岭。**

## Day 29 · 什么是评测（概念课）

**一个残酷的事实**：你现在的工具，**你没有任何证据证明它准**。

你知道它能跑，你知道它报了问题。但：
- 它报的问题，**真的是问题吗**？（误报）
- 有问题的条目，**它都报出来了吗**？（漏报）
- 客户问你"准不准"，你答什么？

**评测 = 用一批"已知答案"的数据，算出你的准确率。**

**四个必须有的数字**：

| 指标 | 意思 | 怎么算 |
|---|---|---|
| **检出率** | 该报的报出来多少 | 报对的 / 该报的总数 |
| **误报数** | 没问题却报了 | 报错的条数 |
| **单条成本** | 处理一条多少钱 | 总花费 / 条数 |
| **单条耗时** | 处理一条多久 | 总时间 / 条数 |

**今天的任务**：手写一份"标准答案"。

**做法**：从你手上找 20 条字幕（可以是你以前项目的，也可以自己造），**人工标出每一条有什么问题**。

写成 `subtitle-qc/eval/golden.jsonl`，一行一条：

```json
{"file": "bad.srt", "index": "2", "expected": ["overlap"]}
{"file": "bad.srt", "index": "3", "expected": ["too_short"]}
{"file": "good.srt", "index": "1", "expected": []}
```

**规则**：`expected` 是数组，没问题就写 `[]`。

**验收**：
- [ ] 20 条标注完成
- [ ] 至少 5 条是"故意没问题"的（用来测误报）
- [ ] 至少 5 条是"确实有问题"的

## Day 30 · 写评测脚本，算出检出率

**任务**：写 `eval/run_eval.py`：

**验收**：

## Day 38 · 失败重试与"不留半成品"

**问题**：处理到第 5 个文件时崩了，前 4 个的报告已经生成了——**这就是"半成品"**。

**学**：先写临时文件，成功后再改名。

```python
import os

tmp = out_path + ".tmp"
with open(tmp, "w", encoding="utf-8") as f:
    f.write(report)
os.replace(tmp, out_path)   # 原子操作：要么成功，要么没有
```

**任务**：
1. 所有写文件的地方改成"先写 tmp 再 replace"
2. 一个文件失败时，**继续处理下一个**，不要整个崩掉
3. 最后汇报"成功了几个、失败几个、失败的是哪些"

**验收**：
- [ ] 故意让一个文件坏掉，其他文件仍能生成报告
- [ ] 没有留下 `.tmp` 文件
- [ ] 能说清 `os.replace` 为什么比直接写安全
