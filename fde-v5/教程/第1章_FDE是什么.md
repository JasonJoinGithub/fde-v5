# 第 1 章 · FDE 是什么

> **先看懂这一章，再去练。** 不知道逻辑就照着练，练到一半会崩。

---

## 1. 一句话定义

FDE（Forward Deployed Engineer，前沿部署工程师）不是"高级程序员"，也不是"懂技术的销售"。

准确的一句是：

> **被派到客户现场，把模型能力变成客户流程里真实在跑的东西，并且对"它到底有没有用"负责的工程师。**

三个关键词，缺一个就不是 FDE：

| 关键词 | 意思 | 缺了会怎样 |
|---|---|---|
| **现场** | 在客户的环境里做，不是在自己公司做 | 做出来的东西客户用不了 |
| **亲手** | 自己写、自己调、自己修 | 变成"提需求的"，不是 FDE |
| **负责** | 不是"交付了"，是"有人用了、指标变了" | 变成外包 |

> 大厂招 FDE 时，筛的就是这三样。会写代码的人很多，愿意去现场、并且扛结果的人很少。

---

## 2. 它从哪来：一个 2009 年的岗位，为什么 2026 年爆了

### 2009：Palantir 造了这个词

"Forward Deployed" 是军事术语——**前沿部署**。意思是把兵力放到最靠近战场的地方，而不是待在后方指挥部。

Palantir 当年做的事：政府和大企业的数据在客户自己的系统里，产品没法靠远程支持解决。所以他们把工程师**派到客户那里住下来**，跟客户一起把数据接上、把系统跑起来。这个岗位叫 FDSE（Forward Deployed Software Engineer）。

### 2023–2026：为什么突然全行业都在抢

因为出现了一个巨大的断层：**模型能力过剩，但企业落地大面积失败。**

| 时间 | 公司 | 动作 |
|---|---|---|
| 2026 | OpenAI | 成立 Deployment Company，初始投资 **超 40 亿美元**，收购 Tomoro 带入约 150 名前线工程师 |
| 2026 | Anthropic | 联合黑石、高盛等组建企业 AI 实施公司 Ode，约 **15 亿美元**承诺资本 |
| 2026 | AWS | 投入 **10 亿美元**建 FDE 组织；作战方式是「5–6 人小队，45 天周期，嵌入客户现场」 |
| 2026 | 字节火山引擎 | 国内直接开 **Forward Deployed Engineer** 岗，要求「熟练掌握 Vibe coding」 |
| 2026 | 阿里云 | 对应岗位叫「大模型资深交付专家」「AI 大模型解决方案工程师」，按行业拆 |

> Gartner 预测：到 2026 年底，**超 85% 的技术供应商将以 FDE 作为 AI 的核心交付方式**。

---

## 3. 为什么这个岗位存在：三个断层

### 断层一：能力断层 —— 模型会给答案，企业要的是"在流程里跑对"

调 API 产出一段文字，谁都会。但企业要的是：这段文字进入审批流、写进工单、触发付款、并且**错了有人担责**。

中间隔着的不是"更聪明的模型"，是**系统集成、权限、边界、兜底**。

### 断层二：数据断层 —— 数据在 7 个系统里，又脏又不敢出域

- 字段名是拼音缩写，没有文档
- 同一个客户三个 ID，没有主键
- 脏数据 30%，没人敢用
- 敏感数据混在里面，不能给模型看
- 内网、等保、数据出境——硬墙

**所以真正的活不是"收集数据"，是"把数据变成能用的东西"。** 这件事八成是工程和流程，不是算法。

### 断层三：组织断层 —— 谁签字、谁维护、员工愿不愿意用

这一层最容易被技术人忽略，也是项目死得最多的地方。

| 数字 | 含义 |
|---|---|
| **95%** | 企业生成式 AI 试点对损益没有可测量影响（MIT） |
| **70%** | 领先者与落后者的差距，投入发生在技术层之外（BCG） |
| **40%** | Gartner 预测到 2027 年底被取消的 Agent 项目比例 |
| **7539** | 2025 年国内大模型中标项目数，295 亿元，同比 +356% |

> **所以 FDE 的本质工作，不是让模型更聪明，是让系统在烂环境里可靠。**
> 需求爆炸和交付失败是同一枚硬币的两面——这个缺口，就是 FDE 的岗位。

## 4. 一个项目周期：FDE 到底怎么干活

| 阶段 | 在干什么 | 产出 | 对应课程 |
|---|---|---|---|
| **① Discovery** | 访谈、看流程、找真问题 | 问题定义 + 成功指标 | W10 |
| **② Scoping** | 定做什么、**明确不做什么**、验收标准 | SOW | W9 |
| **③ Prototype** | 最快路径跑通一条链路 | walking skeleton | W1–W4 |
| **④ Evaluate** | 建黄金集，算准确率，分析 badcase | 带数字的评测报告 | **W5** |
| **⑤ Production** | 部署、权限、日志、监控、恢复 | 服务 + runbook | W6–W8 |
| **⑥ Handover** | 文档、培训、support 期 | 四件套 + 培训 | W9 |

### 一天大概怎么过

| 时间 | 在干什么 | 占比 |
|---|---|---|
| 上午 | 客户访谈 / 需求对齐 | 25% |
| 上午 | 数据摸底 | 15% |
| 下午 | 写代码 / 搭系统 | 30% |
| 下午 | 调评测 | 10% |
| 傍晚 | 写材料 | 15% |
| 随时 | 救火 | 5% |

> **写代码只占 30%。** 另外 70% 是沟通、数据、材料、救火。
> 这就是为什么"技术很强但不爱说话"的人做不好 FDE。

## 5. 它不是什么：和五个相邻岗位的区别

| 岗位 | 核心动作 | 为什么不是 FDE |
|---|---|---|
| **产品经理** | 定义做什么，交给研发 | PM 说"交给研发"，FDE 说"我做出来了，你试试" |
| **售前 / 解决方案架构师** | 卖方案、做 PoC | 售前卖梦，FDE 圆梦 |
| **实施工程师** | 按清单配置、安装 | 实施按别人定好的清单干；FDE 自己定义清单 |
| **普通后端工程师** | 在干净环境写服务 | SWE 在自家代码库；FDE 在客户烂摊子里跑起来 |
| **咨询顾问** | 给建议、出报告 | 顾问交付 PPT；FDE 交付能跑的代码 |

> **记住这句话**：FDE 是"能自己把产品做出来的产品经理"。
> 他有产品经理的判断力，但不接受"这个需求交给研发"——因为他自己就是研发。

**为什么这个区分对你重要**：你的强项（行业判断、需求翻译、文档）像产品经理；弱项（读码、改码、验证）正是研发那一半。所以学习重点不是再学产品思维，而是补上研发那一半。

## 6. 能力模型：三层，缺哪层都做不成

```
┌──────────────────────────────────────┐
│ 上层 · 商业判断                       │
│ 这值不值得做 / 客户的真问题是什么     │  ← AI 替不了，靠行业经验
├──────────────────────────────────────┤
│ 中层 · 方案与边界                     │
│ 拆步骤 / 定边界 / 指挥 AI             │  ← 判断力变成可执行
├──────────────────────────────────────┤
│ 下层 · 实现与验证                     │
│ 读码/改码/调试/评测/部署/交付         │  ← 12 周要补的
└──────────────────────────────────────┘
```

- 只有上层 = 咨询顾问
- 只有下层 = 外包程序员
- **三层都有 = FDE**

## 7. 用在哪：场景清单，以及你的切入点

### 通用场景

| 场景 | 典型任务 |
|---|---|
| 企业知识库 / 文档问答 | 把内部制度、合同、手册变成能问的 |
| 文档处理与合规审查 | 合同比对、条款抽取、发票核对 |
| 工单 / 客服 Agent | 分派、回复、升级、人工兜底 |
| 数据分析助手 | 自然语言查库、出报表、异常解释 |
| 内容生产流水线 | 文案、字幕、素材检索、审核 |
| 质检 / 巡检 | 图像识别 + 人工复核 + 证据链 |
| 代码迁移 / 现代化 | 老系统改造、前端迁移 |
| 流程自动化 | 订单、审批、对账、报表 |

### 垂直行业

金融风控 · 医疗 · 制造质检 · 政企审批 · 零售电商 · 能源电力 · 法律服务 · 教育 · 运营商 · 汽车 · **影视内容**

> 阿里云的 FDE 岗就是按行业开的：政企、汽车、通用 MaaS。字节的是按系统开：财务/HR、算法方向。

### 你的切入点：影视 / 内容

因为「懂 Avid/Resolve/Dailies 的工程师」几乎不存在，「懂 AI 的剪辑师」更不存在。这个交叉点上，12 年经验是溢价。

### 但跨行业的正确姿势：万能四问

| # | 问 | 影视 | 电商 | 制造 |
|---|---|---|---|---|
| 1 | 现在这件事谁在做？ | 剪辑助理 | 运营 | 质检员 |
| 2 | 输入是什么、输出是什么？ | 素材 → 时间线 | 商品图 → 详情页 | 零件 → 合格/不合格 |
| 3 | 哪步确定、哪步靠判断？ | 转码确定，选条靠判断 | 排版确定，卖点靠判断 | 测量确定，瑕疵判定靠判断 |
| 4 | 判断那步能不能变成可评测的标准？ | CPS、术语表 | 转化率、退货率 | 缺陷类型、容忍度 |

## 8. 未来三年：会往哪走，以及风险

> 以下是推断，不是事实。

| 变化 | 什么意思 | 对你的行动 |
|---|---|---|
| **1. FDE 会分层** | 通用"什么都干"的岗位减少，分成 AI builder / 数据 / 行业 / 迁移 | 尽早占一个垂直 |
| **2. 可复用资产成核心产出** | connector、MCP server、skill、eval suite 会像 SDK 一样重要 | 每次交付都沉淀一个可复用件 |
| **3. Agent 可靠性吞并一部分 MLOps** | 状态、重试、审批、回放、审计进入统一交付栈 | 学"失败处理"比学"新框架"值钱 |
| **4. 面试更看现场证据** | "怎么发现、怎么评测、怎么灰度、怎么恢复、怎么交接"占比更大 | demo 要覆盖这五问 |
| **5. 最强 FDE 不会被替代** | 决定做什么、赢得信任、承担结果，仍需人 | 行业判断力是护城河 |

> **最反常识的一句**：模型知识的边际价值在下降，部署判断的边际价值在上升。

### 必须知道的反向风险

FDE 是**成本中心**，不是收入中心。如果企业 AI 采购从"试验"转回"观望"，这个岗位会先收缩。

所以更稳的路径是：**先能接单交付，再谈进大厂。**

## 9. 从底层怎么学：一张知识地图

很多人学 FDE 失败，不是因为不努力，是因为**顺序错了**——先学框架、先学 Agent、先背名词。

| 层 | 学什么 | 够用的标准 | 对应 |
|---|---|---|---|
| **L0 计算机常识** | 程序是什么、文件/路径、终端、报错怎么读 | 能跑起 .py，看懂报错 | W1 D1–D3 |
| **L1 编程** | 变量、条件、循环、函数、列表、字典、文件 | 能手写 60 行小工具 | W1–W2 |
| **L2 数据** | JSON/CSV、清洗、去重、排序、SQL 基础 | 能处理脏数据并出报告 | W2–W4 |
| **L3 工程** | 异常、测试、调试、重构、Git、模块化 | 改一处不弄坏别处 | W3 |
| **L4 系统** | API、HTTP、部署、Docker、日志、指标、评测 | 能上线、能证明它准、能看见它坏 | W5–W8 |
| **L5 AI** | 模型 API、提示词、结构化输出、RAG、成本、兜底 | 能做出稳定可用、算得清成本的功能 | W7 |
| **L6 交付** | 客户发现、SOW、文档、演示、交接 | 别人能照你的文档接手 | W9 |
| **L7 行业** | 一个垂直行业的真实流程 | 能说清这行业"钱在哪、痛在哪" | W10–W12 |

> **为什么不能跳层**：L5 的 AI 能力建立在 L1–L4 上。跳过 L1 直接学 Agent，会变成"能指挥 AI，但看不出它哪里错"的人。那不是 FDE，那是 AI 的重度用户。

**每一层学到 50–80% 就往下走。** 但 L5 的"评测"和 L4 的"能看见它坏"，必须学透——那是分水岭。

## 10. 五个常见误解

| 误解 | 真相 |
|---|---|
| **1. FDE 是"懂 AI 的程序员"** | FDE 是"能交付的工程师"。模型只是被交付的东西之一 |
| **2. 要先成为顶级工程师才能做** | 字节 JD 写的是"3 年经验**或同等实践经验**" |
| **3. FDE 就是驻场外包** | 外包按别人的清单干；FDE 自己定义清单，并把经验沉淀成产品能力 |
| **4. 会用 AI 写代码就够了** | 会用 AI 是入场券，**能看出 AI 写得对不对**才是门槛 |
| **5. FDE 只属于 AI 公司** | 云厂商、行业软件、咨询公司、大企业 IT 都在设这个岗 |

---

> **如果只能记住一句：**
> FDE 不卖模型，不卖方案，**卖的是"这件事在我手里能跑起来，而且我能证明它有用"。**
