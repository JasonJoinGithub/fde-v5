## 卡 2 · 最常见的 10 个报错

| 报错 | 意思 | 先检查什么 |
|---|---|---|
| `SyntaxError` | 语法错 | 括号、引号、冒号是否成对 |
| `IndentationError` | 缩进错 | 是不是混用了空格和 Tab |
| `NameError: name 'x' is not defined` | 变量没定义 | 拼写？定义在下面？ |
| `TypeError` | 类型不对 | 字符串和数字相加？忘了 `str()` / `int()` |
| `KeyError` | 字典里没这个键 | 用 `.get()` 代替 `[]` |
| `IndexError` | 列表越界 | 列表是不是空的？索引从 0 开始 |
| `FileNotFoundError` | 找不到文件 | 路径对不对？`ls` 看看 |
| `ValueError` | 值不对 | `int("abc")` 会报这个 |
| `AttributeError` | 对象没这个属性 | `None.xxx` 最常见 |
| `ModuleNotFoundError` | 模块没装 | `pip install 模块名` |

### 报错怎么读（三步）

```
① 最后一行：错误类型 + 原因
② File "...", line N：哪个文件第几行
③ ^ 指向的位置：大概错在哪
```

> **中间那一大段调用栈，新手可以先不看。**

## 卡 3 · 调试三步法

```
① 复现：让它每次都错
   → 不能复现的 bug 修不了

② 缩小：二分法
   → 注释掉一半代码，看还错不错
   → 在关键位置 print 变量的值

③ 验证：写个测试
   → 证明它修好了
   → 证明以后不会再犯
```

### 临时打点（最快的定位法）

```python
print("=== 到这里了 ===")
print("变量 x =", x)
print("类型 =", type(x))
```

> 新手最有效的调试工具就是 `print`，**不要羞于使用**。

## 卡 5 · Git 最小命令（第 12 周才用，先存着）

```bash
git init                      # 初始化
git add .                     # 把所有改动加入暂存
git commit -m "说明"           # 提交
git status                    # 看当前状态
git log --oneline             # 看历史
```

**三条红线**：
- ❌ 不要 `git add` 包含 API Key 的文件
- ❌ 不要 `git push -f`
- ✅ 提交前跑一次 `git status`，看有没有不该提交的东西

## 卡 7 · 问 AI 的正确姿势

### ✅ 可以问

- "这个报错是什么意思？我应该检查哪几行？"
- "这段代码里 `lambda` 在干什么？用大白话解释。"
- "我想实现 X，有哪几种思路？各自的代价是什么？"
- "帮我 review 这段代码，指出 3 个可能出错的地方。"

### ❌ 不要问

- "帮我写一个完整的 XXX"
- "这段代码我看不懂，你重写一遍"
- "直接给我能跑的版本"

### 判断标准

> **问完 AI 之后，你能不能用大白话讲给一个不懂的人听？**
> 能 → 有效学习
> 不能 → 你只是在搬运
