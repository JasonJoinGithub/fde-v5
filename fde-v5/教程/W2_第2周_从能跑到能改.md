## Day 8 · 命令行参数（让程序能听人话）

### 学一个概念：程序不该把数据写死在代码里

你现在把 `"sample.txt"` 写死在代码里。换一个文件就得改代码——**这在交付里是不可接受的**。

### 亲手敲

新建 `w2/analyze.py`：

```python
# analyze.py
# 用法：python3 analyze.py sample.txt

import sys


def main():
    if len(sys.argv) < 2:
        print("用法：python3 analyze.py <文件路径>")
        return

    path = sys.argv[1]
    print("要分析的文件是：", path)


if __name__ == "__main__":
    main()
```

测试：

```bash
python3 analyze.py
python3 analyze.py sample.txt
```

**你应该看到**：
- 第一次：用法提示
- 第二次：`要分析的文件是： sample.txt`

### 必须理解的点

| 代码 | 意思 |
|---|---|
| `sys.argv` | 一个列表，装着你敲命令时给的所有参数 |
| `sys.argv[0]` | 固定是脚本自己的名字（`analyze.py`） |
| `sys.argv[1]` | 第 1 个参数 |
| `len(sys.argv) < 2` | 说明没给参数 |

> **试着打印 `sys.argv` 看看**，你会立刻明白。

### 验收

- [ ] 不带参数时给提示，不崩
- [ ] 带参数时能读出来
- [ ] 能说清 `sys.argv[0]` 和 `sys.argv[1]` 的区别

## Day 9 · 处理多个文件（循环 + 目录）

### 学一个概念：真实任务永远是"一批"，不是一个

客户不会给你一个文件，他给你一个文件夹。

### 亲手敲

先造测试数据：

```bash
cd ~/fde-code/week1
mkdir -p files
for i in 1 2 3; do
  printf "文件$i第一行\n\n文件$i第三行\n" > files/a$i.txt
done
ls files
```

然后写 `w2/batch.py`：

```python
# batch.py
# 用法：python3 batch.py <文件夹>

import os
import sys


def analyze_one(path):
    """分析一个文件，返回统计字典。"""
    with open(path, "r", encoding="utf-8") as f:
        lines = f.readlines()
    total = len(lines)
    empty = sum(1 for line in lines if line.strip() == "")
    return {"path": path, "total": total, "empty": empty}


def main():
    if len(sys.argv) < 2:
        print("用法：python3 batch.py <文件夹>")
        return

    folder = sys.argv[1]
    if not os.path.isdir(folder):
        print("不是一个文件夹：", folder)
        return

    results = []
    for name in sorted(os.listdir(folder)):
        if not name.endswith(".txt"):
            continue
        path = os.path.join(folder, name)
        results.append(analyze_one(path))

    if not results:
        print("文件夹里没有 .txt 文件")
        return

    for r in results:
        print(r["path"], "总行数", r["total"], "空行", r["empty"])

    total_all = sum(r["total"] for r in results)
    print("---")
    print("共", len(results), "个文件，总共", total_all, "行")


if __name__ == "__main__":
    main()
```

运行：

```bash
python3 batch.py files
```

### 必须理解的点

**1. `os.listdir(folder)` 返回文件名列表**（不含完整路径）
所以要用 `os.path.join(folder, name)` 拼出完整路径。

**2. `if not name.endswith(".txt"): continue`**
`continue` 的意思是"跳过这一个，继续下一个"。这是过滤文件的常用写法。

**3. `sorted(...)` 为什么加**
不加的话，文件顺序是系统给的，不确定。**加 sorted 让结果是可重复的**——这一点在测试里很重要。

### 验收

- [ ] `python3 batch.py files` 能列出 3 个文件并汇总
- [ ] 传一个不存在的文件夹，有提示不崩
- [ ] 能说清 `continue` 的作用
- [ ] 能说清为什么要 `sorted`

## Day 10 · 第一次写测试

### 学一个概念：测试 = 把"它应该怎样"写成代码

前面你都是"跑一下看看对不对"。**这不叫验证，这叫碰运气。**

测试是：**把"输入 X 应该得到 Y"写下来，以后每次改代码，自动检查有没有破坏。**

### 好消息：不用装任何东西

Python 自带测试工具 `unittest`。**不需要 pip install，不需要联网。**

### 先准备一个被测的函数

新建 `w2/analyze.py`：

```python
# analyze.py
import os


def analyze_one(path):
    """分析一个文本文件，返回总行数和空白行数。"""
    with open(path, "r", encoding="utf-8") as f:
        lines = f.readlines()
    total = len(lines)
    empty = sum(1 for line in lines if line.strip() == "")
    return {"path": path, "total": total, "empty": empty}
```

### 亲手敲测试

新建 `w2/test_analyze.py`：

```python
# test_analyze.py
# 运行方式：在 w2 目录下执行 python3 -m unittest test_analyze -v

import os
import tempfile
import unittest

from analyze import analyze_one


def make_file(content):
    """造一个临时文件，返回路径。"""
    fd, path = tempfile.mkstemp(suffix=".txt")
    with os.fdopen(fd, "w", encoding="utf-8") as f:
        f.write(content)
    return path


class AnalyzeTest(unittest.TestCase):

    def test_normal_file(self):
        path = make_file("第一行\n第二行\n")
        result = analyze_one(path)
        self.assertEqual(result["total"], 2)
        self.assertEqual(result["empty"], 0)
        os.remove(path)

    def test_empty_lines(self):
        path = make_file("第一行\n\n\n第四行\n")
        result = analyze_one(path)
        self.assertEqual(result["total"], 4)
        self.assertEqual(result["empty"], 2)
        os.remove(path)

    def test_empty_file(self):
        path = make_file("")
        result = analyze_one(path)
        self.assertEqual(result["total"], 0)
        self.assertEqual(result["empty"], 0)
        os.remove(path)


if __name__ == "__main__":
    unittest.main()
```

### 运行

```bash
cd ~/fde-code/week2
python3 -m unittest test_analyze -v
```

**你应该看到**：

```
test_empty_file (test_analyze.AnalyzeTest) ... ok
test_empty_lines (test_analyze.AnalyzeTest) ... ok
test_normal_file (test_analyze.AnalyzeTest) ... ok

----------------------------------------------------------------------
Ran 3 tests in 0.001s

OK
```

### 必须理解的点

**1. `self.assertEqual(a, b)` 是什么**
断言"a 应该等于 b"。相等就过，不等就报错。

常用的还有：
- `self.assertTrue(x)` — x 应该是真
- `self.assertIn(a, b)` — a 应该在 b 里
- `self.assertRaises(ValueError)` — 应该抛出某个错误

**2. 为什么测试要写在一个 class 里**
`unittest` 的规矩：测试类继承 `unittest.TestCase`，方法名以 `test_` 开头。
**不以 `test_` 开头的方法，不会被执行。**

**3. 为什么要造临时文件**
测试不能依赖 `sample.txt`（它可能被改、被删）。**每个测试自己造数据，才可靠。**

**4. 测试最重要的价值**

不是"证明它对"，是**"以后你改坏了，它会告诉你"**。

> **现在做一次实验**：打开 `analyze.py`，把
> `empty = sum(1 for line in lines if line.strip() == "")`
> 改成 `empty = 0`，再跑一次测试。
>
> 你会看到：
> ```
> AssertionError: 0 != 2
> FAILED (failures=1)
> ```
> **这就是测试的价值。** 改完记得改回去。

### 动手改（必做）

1. 加第 4 个测试：一个只有空白行的文件（`"\n\n\n"`），total=3, empty=3
2. 加第 5 个测试：一个不存在文件的测试，用 `self.assertRaises(FileNotFoundError)`，需要改成 `with self.assertRaises(...):`
3. 故意改坏一处逻辑，确认测试能抓到，然后改回来

### 验收

- [ ] 5 个测试全过
- [ ] 故意改坏代码，能看到 `FAILED`
- [ ] 能说清 `assertEqual` 在干什么
- [ ] 能说清"为什么方法名必须以 test_ 开头"

### 关于 pytest（可选，现在不用管）

你可能在网上看到别人用 `pytest`。它更好用，但**需要额外安装**，而你的系统 Python 可能装不上。
**这 12 周我们全程用 `unittest`，够用，而且零依赖。**
以后进了公司，公司环境里通常已经装好了 pytest，那时再用。

## Day 11 · 调试：程序不按预期跑，怎么找原因

### 学一个概念：调试 = 缩小范围，不是猜

新手调试：改一下、跑一下、不行再改一下。
老手调试：**先确定"哪一段有问题"，再在那一段里找。**

### 三道练习题（我给你坏代码，你找 bug）

**练习 1**：`w2/bug1.py`

```python
def average(numbers):
    total = 0
    for n in numbers:
        total += n
    return total / len(numbers)

print(average([]))
```

运行它。**先不要改，回答**：报什么错？为什么？

然后修：让空列表返回 0，而不是崩。

**练习 2**：`w2/bug2.py`

```python
def count_word(text, word):
    count = 0
    for w in text.split():
        if w == word:
            count += 1
    return count

print(count_word("apple Apple APPLE", "apple"))
```

运行它。输出是 1，但**你可能期望是 3**（大小写不敏感）。
回答：这是 bug 吗？还是设计如此？
然后：改成大小写不敏感，并写一个测试。

**练习 3**：`w2/bug3.py`

```python
def main():
    items = []
    for i in range(3):
        items.append(lambda: i)
    for f in items:
        print(f())

main()
```

运行它。输出是 `0 1 2` 还是 `2 2 2`？

> 这是 Python 最著名的坑之一：**闭包在循环里捕获的是变量本身，不是当时的值。**

### 调试三步法（背下来）

```
① 复现：让它每次都能错（不能复现的 bug 修不了）
② 缩小：二分法——注释掉一半代码，看还错不错
③ 验证：改完后，写一个测试，证明以后不会再错
```

### 验收

- [ ] 三个 bug 都说清了"为什么错"
- [ ] 三个都修好了
- [ ] 能背出调试三步法
- [ ] 给 bug2 写了一个测试

## Day 12 · 重构：把一坨代码拆开

### 学一个概念：拆函数的标准不是"太长"，是"这件事有没有名字"

### 任务

下面这段 40 行的"一坨"代码，拆成 3 个函数。

新建 `w2/messy.py`：

```python
import sys

path = sys.argv[1]
f = open(path, encoding="utf-8")
lines = f.readlines()
f.close()
total = len(lines)
empty = 0
words = 0
for line in lines:
    if line.strip() == "":
        empty += 1
    words += len(line.split())
max_len = 0
for line in lines:
    if len(line.strip()) > max_len:
        max_len = len(line.strip())
print("文件:", path)
print("总行数:", total)
print("空行:", empty)
print("词数:", words)
print("最长行:", max_len)
```

**你的任务**：

1. 拆成 3 个函数：`read_lines(path)` / `compute_stats(lines)` / `print_stats(path, stats)`
2. 每个函数写一句 docstring（说清输入输出）
3. 主流程放进 `main()`，用 `if __name__ == "__main__":` 调用
4. **拆完之后，改 `print_stats` 里的输出格式，确认 `compute_stats` 一行都不用改**

> 第 4 步是关键：**它证明你的拆分是对的**——改一处不影响别处。

### 验收

- [ ] 3 个函数各自职责单一
- [ ] 改输出格式时，统计逻辑没动
- [ ] 能说清"为什么这么拆"
