# 读代码判代码：不用会写，但要会判（面包类比）

> 对应 App 里的 W0 Day 6。这一课不写代码，只练判断。

## 这算哪种能力

它叫**技术判断力**，也叫**架构理解力、代码评审与验收能力**。

- 不是编程能力：不用会写代码，不用背语法。
- 不是算法能力：不用推公式、不用刷题。
- 是 FDE 最核心的能力之一：你把需求翻译成机器能操作的语言，交给 Claude、Codex 去写，写完之后你要能看出来它做了什么、做得好不好、交付之后哪些能用、哪些不能用。

一句话：**模型是手，你是验收的人。手可以换，验收不能换。**

## 面包类比：三步对应

| 做面包 | 对应到代码 | 你要能看出来 |
|---|---|---|
| 不用知道每一步加了多少克糖和面粉 | 不用知道每行代码是什么意思 | —— |
| 但要知道面包是怎么做出来的：第一步做什么、第二步做什么、第三步做什么 | 框架是什么：入口在哪、数据从哪来、经过哪几步、到哪去 | 能说出一段代码的框架，不用背代码 |
| 水加多了还是少了 | 数据多了还是少了、脏不脏、边界处理了没有（空数据、超长、重名、断网） | 至少指出 1 处边界问题 |
| 糖加多了还是少了 | 功能做多了还是做少了、过度设计还是缺功能 | 能说出哪一步多做了、哪一步没做 |
| 温度是高了还是低了 | 性能和成本：跑得快不快、花钱多不多、模型是不是选太大了 | 能问一句“这一单多少钱、要跑多久” |
| 出炉之后哪些能吃、哪些不能吃 | 交付之后哪些能用、哪些不能用、哪些要人先审 | 写出验收清单，分三栏 |

## 读代码三步法：入口 → 数据流 → 副作用

拿到一段 AI 写的代码，别从第一行开始读，按这个顺序：

1. **入口**：程序从哪开始跑？找到入口，再顺着往下读。
2. **数据流**：数据从哪来、经过哪几步、到哪去？画出来，错的地方就藏在这条线上。
3. **副作用**：代码除了返回结果，还改了什么？写了文件、发了请求、删了数据？副作用是最容易出事的地方，先问它还改了什么。

每次让 Claude 讲代码，都让它按这个顺序讲，用 plain language，不要贴代码。

## 判好坏：三层

1. **对不对**：评测过没有？20 个案例里过了几个？
2. **全不全**：边界和异常处理了没有？空数据、超长、断网、权限不足，会怎么样？
3. **稳不稳**：权限、成本、失败了怎么办？错了能回滚吗？日志在哪？

三层都过，才能说“能用”。只过第一层，叫“演示那天没崩”。

## 验收清单：交付时照单点

| 能用 | 不能用 | 要人先审 |
|---|---|---|
| 写清楚，跑过评测的 | 没过评测的、没处理边界的 | 要写文件、要发请求、要删数据的 |
|  |  | 超过预算、涉及敏感数据的 |

验收清单写在前面，客户点头，交付时照单点。

## 练习：问 Claude 一个它答不上来的问题

“这段代码在什么情况下会坏？”

能说出边界的，才是好代码。说不出来的，先记下来，那是你的风险清单。
